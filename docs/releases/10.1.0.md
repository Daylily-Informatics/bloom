# Bloom 10.1.0 — attributable Atlas tube operations on TapDB 11

This release pins TapDB 11.0.0. It requires native fenced database adoption and
runtime binding before new writers start. A previous image is not a sufficient
database rollback after adoption.

Verified browser/service authentication supplies explicit native attribution.
API-token calls identify the authenticated delegated credential, rather than
claiming an unverified upstream human. Native CLI writes accept an explicit
`--attribution` envelope. Permission reads no longer seed missing groups.

Tube request/registration and Atlas/Dewey reference operations supply native
revision preconditions, including retained inactive assertions and complete
authority-owned active sets. Conflicts return 409. Existing tube request keys,
identity assertions and reconciliation receipts remain the retry authority.
The Atlas external reference retains its own identity when owner verification
or registration completes later.

Focused checks are authored, not run at publication preparation. TapDB's
package qualification is not Bloom/Atlas behavioral acceptance. No historical
data repair, sibling deployment or new TapDB release is included.

The cross-service controlling ledger is retained in Atlas at
`docs/plans/20260929T192741Z_atlas_accession_revision_ledger.md`.
